# AI 활용 내역

ScanOps 개발 과정에서 활용한 생성형 AI/AI 코딩 도구와 활용 범위, 그리고 AI 생성 코드의 검증·수정 방식을 기록합니다.

## 1. 활용한 AI 도구

| 도구 | 용도 |
|------|------|
| **Claude Code (Anthropic)** | 멀티 레포(frontend/backend/model/infra) 아키텍처 설계, 백엔드·모델 코드 작성, 리팩토링, 벤치마크 스크립트, GitHub Actions 미러링 자동화 |
| **Anthropic Claude (Sonnet)** | 자체 파인튜닝 모델(Qwen3.5-9B)의 취약점 탐지 정확도를 비교 검증하는 벤치마크 비교군, 코드 리뷰 보조 |


## 2. 활용 범위

- **설계 단계**: 레포 분리 구조, 서비스 간 의존성, SaaS 전환(인증·구독·사용량 게이트) 설계안 정리에 AI를 활용했습니다. 최종 아키텍처 결정은 팀원 논의를 거쳐 확정했습니다.
- **개발 단계**: 백엔드 `AiRouter` 폴백 구조, Joern CPG·RAG 하이브리드 파이프라인, 프론트엔드 FSD 구조 코드를 AI 페어 프로그래밍 방식으로 작성했습니다. 비즈니스 로직(구독 게이트, 소유권 인증, 코드 즉시 폐기 정책 등 보안·프라이버시에 직결되는 부분)은 AI 초안을 팀원이 직접 재작성하거나 라인 단위로 검토했습니다.
- **모델 단계**: QLoRA 학습 데이터 생성, 학습 스크립트, GGUF 양자화, 벤치마크 자동화 과정에서 AI를 활용해 반복 작업을 가속했습니다.
- **미사용 범위**: 사용자 코드/개인정보를 다루는 실제 운영 파이프라인(스캔 오케스트레이션의 데이터 삭제 로직, 결제 연동)은 AI가 생성한 코드를 그대로 배포하지 않고, 반드시 팀원이 직접 작성하거나 전면 재검토 후 반영했습니다.

## 3. AI 생성 코드의 검증·수정 방식

1. **리뷰 필수**: AI가 생성한 모든 코드는 PR 형태로 올려 팀원 최소 1인이 리뷰한 뒤 병합합니다. GitHub Actions 기반 자체 서비스(ScanOps)로 PR diff를 자체 스캔해 취약점 여부를 교차 확인합니다.
2. **테스트 검증**: 백엔드는 Spring Boot 테스트, 모델 서버는 벤치마크 스크립트(내부 홀드아웃 1,197건 + PrimeVul·CleanVul 외부 벤치마크)로 AI가 작성/수정한 로직의 동작을 정량 검증합니다.
3. **보안 민감 영역 이중 확인**: 인증·소유권 인증·사용량 게이트·코드 삭제 로직 등 보안/프라이버시에 직결되는 코드는 AI 초안을 그대로 채택하지 않고, 팀원이 직접 로직을 재작성하거나 단위 테스트로 동작을 재확인합니다.
